# Social Trend Radar 完全無料構成・費用試算 v1

**状態**: レビュー待ち  
**作成日**: 2026-10-09  
**前提**: 既存アプリへ統合せず、独立した1つのツールとして提供する。

## 1. 結論

推奨は、**独立Webアプリ + Discord Bot + 自宅Macワーカー**を主系にし、Slackを同じ保存APIへつなぐ構成。

- 複数メンバーはDiscordへ動画リンクを送るだけで保存できる。
- Slackはマーケチーム内の第2入口として追加できる。
- ブラウザ管理画面、保存API、Bot、ローカル分析は同じ製品の構成要素であり、既存アプリには接続しない。
- Instagram / TikTokのログイン済み画面は、専用調査アカウントで閲覧専用の自動巡回を行う。いいね、フォロー、コメント、投稿、リポスト、DM等の書き込み操作は行わない。
- 月額サービス利用料は0円にできる。ただし、自宅Macの電気代、回線代、機器消耗は0円ではない。

## 2. 無料構成

```text
メンバー
  ├─ Discord Bot（主入口）──────────┐
  ├─ Slack Bot（社内入口）──────────┤
  ├─ Chrome拡張（PC、手動導入）─────┤
  └─ 独立Webアプリ ─────────────────┤
                                      ↓
Cloudflare Free
  Workers（API）+ D1（共有キュー・共有データ）
                                      ↑ ↓ 外向き通信のみ
自宅MacBook
  Bot常駐 / ジョブ取得 / YouTube API / ローカルSQLite
  ルール判定 / ローカル埋め込み / Jev任意利用 / 閲覧専用ブラウザ操作

GitHub → Vercel Hobbyで静的管理画面を配信
```

Vercel Hobbyは非商用期間の画面配信に限る。営利利用へ移る場合はCloudflare Pagesへ移行するかVercel Proを選ぶが、「サービス請求0円」を優先する場合はCloudflare Pagesへ移行する。

自宅Macへ外部から直接接続させない。MacがDiscord・Slack・Cloudflareへ外向きに接続し、Cloudflare D1のジョブを取りに行く。これにより固定IP、ポート開放、有料サーバーを不要にする。

## 3. Bot候補比較

| 候補 | 利用料 | 配布しやすさ | 一般認知 | 自宅Macとの接続 | 制約 | 判断 |
|---|---:|---|---|---|---|---|
| Discord | 0円 | 招待URLでサーバーへ追加 | 若年層・クリエイター領域で通じやすい | Gateway WebSocket。公開URL不要 | APIレート制限。規模拡大時はBot審査・sharding | **主入口** |
| Slack | 0円 | ワークスペースごとにインストール | 業務利用では高い | Socket Mode。公開URL不要 | Freeは10アプリ・履歴90日。Socket ModeアプリはMarketplace掲載不可 | **社内第2入口** |
| LINE | 0円開始 | 友だち追加で分かりやすい | 日本の一般層には最も説明しやすい | 公開Webhookが必要。Workersで受信可 | 無料枠の能動配信は月200通。受信直後のReplyは課金対象外 | 公開拡大時の追加候補 |
| Telegram | 0円 | Botリンクで追加 | 日本の一般層には相対的に弱い | ロングポーリングまたはWebhook | 1チャット約1通/秒、グループ20通/分等 | 初期不採用 |

Discord Botはリンク、任意メモ、発見経路だけを受け取る。チャンネル履歴の一括取得、会話解析、DM保存はしない。Slackも同じ方針とする。

## 4. ツール別費用

2026-10-09時点。無料枠は将来変更され得るため、実装では上限到達時に失敗停止し、有料プランへ自動移行しない。

| 区分 | ツール | 料金・無料上限 | 本構成の想定 | 請求額 |
|---|---|---|---|---:|
| Bot | Discord Bot API | API利用料なし。通常のグローバル上限は概ね50 req/s | 数人〜数十人のリンク保存 | 0円 |
| Bot | Slack App | Free workspaceは0 USD、履歴90日、最大10アプリ | 社内ワークスペース1つ、Socket Mode | 0円 |
| Bot候補 | LINE Messaging API | 無料プランは能動配信200通/月。Replyはカウント外 | 初期未使用。追加時は即時返信だけを基本 | 0円 |
| Bot候補 | Telegram Bot API | Bot APIは無料。送信レート制限あり | 初期未使用 | 0円 |
| Web | Vercel Hobby | 非商用利用の無料枠 | Git連携した独立Web画面。営利化時は使用しない | 0円 |
| Web代替 | Cloudflare Pages | Freeは月500ビルド、1サイト2万ファイル | 営利化後も0円を維持する場合の移行先 | 0円 |
| API | Cloudflare Workers | Freeは10万request/日、CPU 10ms/呼出 | 保存・一覧・同期API | 0円 |
| DB | Cloudflare D1 | Freeは500万row read/日、10万row write/日、5GB | 共有キュー・チーム共有データ | 0円 |
| 接続 | Cloudflare Tunnel | 全プランで利用可 | 通常は不要。臨時デバッグのみ | 0円 |
| 収集 | YouTube Data API | 金銭課金ではなく無料quota。既定は `search.list` 100回/日、その他合計10,000 units/日 | 検索を節約し、IDをまとめて `videos.list` | 0円 |
| 収集 | TikTok oEmbed | 公開エンドポイント。認証不要 | URLからタイトル・作者・埋込情報。指標取得には使えない | 0円 |
| 収集 | Instagram | 任意公開Reelを横断取得できる無料公式APIはない | URLと人が見た情報を保存 | 0円だが情報量限定 |
| AI | Jev / Vercel AI Gateway | Jevは入力100万tokenあたり$0.04。Gateway無料対象なら月$5 credit | 曖昧な分類・画面判断だけ。上限到達時はルール判定へ戻す | 0円に固定 |
| AI | ローカル埋め込み・ルール分類 | OSSをMacで実行 | 重複排除、クラスタ、通常分類 | 0円 |
| 自動操作 | Playwright + Chromium | OSS | Instagram / TikTokの閲覧専用巡回 | 0円 |
| DB | SQLite / DuckDB | OSS | Mac側の正本・分析 | 0円 |
| 配布 | Chrome拡張・unpacked | 開発者モードで手動導入は無料 | チーム内配布 | 0円、導入負担あり |
| 配布 | Chrome Web Store | 開発者登録に一回限りの登録料が必要 | **完全無料条件から外れるため使わない** | 0円構成では不採用 |
| ドメイン | `*.pages.dev` | 無料サブドメイン | 専用ドメインは買わない | 0円 |

### 無料枠を超えない実装ルール

1. Cloudflareに支払方法を登録しない。Free上限到達時は翌日まで停止させる。
2. D1はページング必須とし、全件走査を禁止する。分析の重いクエリはMac側SQLite / DuckDBで行う。
3. YouTube検索は最大100回/日より低い内部上限を設定し、同じ検索結果をキャッシュする。
4. Jevは月間tokenカウンタを持ち、無料creditの80%相当で停止する。
5. Chrome Web Store、独自ドメイン、有料監視、SMS、メール配信は採用しない。

## 5. Jev費用試算

Jevの表示価格を入力100万tokenあたり$0.04、無料creditを月$5とすると、理論上は**1億2,500万入力token/期間**まで$5内。ただし、Jevが無料対象モデルであること、レート制限、無料creditの条件は利用時に再確認する。

| 使い方 | 仮定 | token/月 | 定価換算 | 無料構成の動作 |
|---|---|---:|---:|---|
| 保存投稿の補助分類 | 10,000件 × 500 token | 500万 | $0.20 | 実行可 |
| 画面操作の判断 | 1,000件 × 20判断 × 1,000 token | 2,000万 | $0.80 | 運用枠内 |
| 大量画面操作 | 5,000件 × 20判断 × 1,000 token | 1億 | $4.00 | 上限近く。推奨しない |

この数字は実測ではなく予算設計用の仮定。実装後に1週間のtokenログで置き換える。

Jevはスクリーンを自動理解して何でも操作する完成品ではない。実際には、PlaywrightやmacOSアクセシビリティ層が「現在状態」と「押してよい操作候補」を渡し、Jevが `CLICK / SCROLL / SAVE / STOP` のような型付き選択を返す。固定処理はコード、状態が揺れる箇所だけJevにする。

共有された[Xの実例](https://x.com/tf_makimaki/status/2104008619821838820?s=20)は、音声からPCを操作するJev利用例として実在を確認した。ただし、SNS大量巡回や長期安定稼働を実証したものではない。

## 6. 自宅Macの実コスト

サービス請求を0円にしても電気代は残る。追加消費電力を家庭の契約単価31円/kWhと仮定した場合:

| 平均追加消費電力 | 月間電力量 | 月額目安 |
|---:|---:|---:|
| 5W | 3.6kWh | 約112円 |
| 10W | 7.2kWh | 約223円 |
| 20W | 14.4kWh | 約446円 |

計算式は `W × 24時間 × 30日 ÷ 1000 × 電力単価`。Macが元から常時稼働している場合は総消費ではなく追加分で見る。別途、インターネット回線、バッテリー、SSD、故障時停止のコストがある。

## 7. Instagram / TikTok自動操作の扱い

### 技術的には可能

- 専用Chrome profileをPlaywrightで起動する。
- DOM / アクセシビリティ情報から表示カード、リンク、表示指標を読む。
- ルールで確定できない画面遷移だけJevに選ばせる。
- 保存先はURL、表示時刻、表示値、観測レーン。動画本体、Cookie、ログイン情報は保存しない。

### 運用上の前提

- 本人判断により、閲覧専用の自動巡回を標準収集機能として許可する。
- アカウント停止、CAPTCHA、画面変更による故障は運用上の外部制約として監視するが、採用を止める条件にはしない。
- ログイン済みおすすめ面だけに依存すると1アカウントの嗜好を増幅するため、複数調査アカウントとExternal Baselineを併用する。

### 採用境界

- 標準: Bot / 拡張保存、YouTube公式API、TikTok oEmbed、専用調査アカウントによるInstagram / TikTok巡回。
- 許可操作: 閲覧、スクロール、タブ遷移、URL取得、画面に表示された公開情報の記録。
- 禁止操作: いいね、フォロー、コメント、投稿、リポスト、DM、商品購入、設定変更。

## 8. フィルターバブル対策の更新

Jev自動操作を増やすだけでは汎用性は上がらない。アカウントと観測設計を分ける。

| レーン | 割合の初期値 | 取得方法 | 役割 |
|---|---:|---|---|
| Personalized | 25% | メンバーの手動保存 | 早期兆候 |
| Fixed Panel | 25% | 固定クリエイター・固定テーマ | 継続比較 |
| Broad Discovery | 25% | 毎週入替の語彙・隣接ジャンル | 未知探索 |
| External Baseline | 25% | 公式API・ランキング・外部チャート | 個人推薦から独立した基準 |

自動調査は第5レーンにせず、`selection_method=auto_observed`として取得方法を記録する。取得内容は目的に応じてFixed Panel / Broad Discovery / External Baselineのいずれかへ所属させ、4レーン構成を維持する。評価時は「独立投稿者数」「複数レーン一致」「同じ型の再利用」「投稿者通常値からの上振れ」を重視し、単一アカウントのおすすめ出現回数をトレンド根拠にしない。

## 9. 初期リリース範囲

### 含める

- 独立Webアプリ
- Discord Bot
- メンバー招待コード
- URL正規化、重複排除、発見経路、任意メモ
- YouTube公式API
- Instagram / TikTokのURL保存と取得可能な公開情報
- Instagram / TikTokの閲覧専用自動巡回
- Mac側SQLite、ルール判定、無料枠メーター
- Chrome拡張のunpacked配布

### 含めない

- 既存アプリとの統合
- Chrome Web Store公開
- 動画ファイル保存
- 有料API、有料ホスティング、独自ドメイン
- Botからの大量プッシュ通知
