# Social Trend Radar フロントエンド・同期仕様 v1

**状態**: レビュー待ち  
**作成日**: 2026-10-09

## 1. データ管理の結論

DBファイルをGitで管理しない。構成は次の3層に分ける。

| 層 | 置き場所 | 役割 | 正本か |
|---|---|---|---|
| SQLite | 自宅Mac | 投稿、観測、Bot入力、ジョブ、ラベルのトランザクション保存 | **正本** |
| DuckDB | 自宅Mac | 集計、時系列、クラスタリング、重い分析 | SQLiteから再生成可能 |
| Cloudflare D1 | クラウド無料枠 | チーム画面用read model、受信キュー、同期状態 | 閲覧用コピー |

Gitへ入れるもの:

- アプリコード
- SQLスキーマ
- マイグレーション
- seed用の匿名サンプル
- 設定テンプレート

Gitへ入れないもの:

- `*.sqlite`、`*.db`、WAL、DuckDB本体
- Cookie、セッション、Bot token、API key
- 投稿の大量観測データ
- メンバーの個別メモを含むバックアップ

DBは更新のたびにバイナリ差分が大きくなり、競合・破損・秘密情報流出が起きるためGitには向かない。バックアップはMacのTime Machineまたは日次SQLite snapshotを使う。

## 2. リアルタイム同期

```text
Bot / 自動巡回 / API
        ↓
SQLite transaction
  ├─ posts / captures / metrics / clusters
  └─ sync_outbox（同じtransactionで追加）
        ↓ 2秒ごと、または分析完了直後
Mac Sync Worker
        ↓ HTTPS + idempotency key
Cloudflare Worker
        ↓ upsert
D1 read model
        ↓ /api/changes?cursor=...
チームのWeb画面
```

### 同期保証

- SQLite保存と`sync_outbox`追加を同じtransactionで行う。
- 各変更に`entity_id + version`を持たせ、再送しても二重登録しない。
- D1同期成功後にoutboxを完了扱いにする。
- Mac停止中もBot / Webから受けたリンクはD1の受信キューへ残し、復帰後にMacが回収する。
- 生のCookie、ブラウザセッション、動画本体はD1へ送らない。

### 画面反映速度

- 画面表示中: 15秒間隔で差分取得
- 分析ジョブ詳細を開いている間: 5秒間隔
- バックグラウンドタブ: 60秒間隔
- `ETag` / cursorを使い、変更がなければ本文を返さない。

10人が8時間、15秒間隔で開いても約19,200 request/日。Workers Freeの10万request/日内に収まる。真のWebSocket配信より実装と復旧が単純で、この用途では十分リアルタイムに見える。

## 3. フロントエンドの設計思想

テーマは**Editorial Intelligence Console**。SNS管理画面らしいカラフルなカード集ではなく、編集会議でそのまま判断に使える「根拠付き観測紙面」にする。

画面を開いて10秒以内に答えられるべき質問:

1. 今、何が伸び始めているか。
2. 単一アカウントのおすすめではなく、どこまで広がっているか。
3. 表面的な音源流行なのか、再利用できる構造・欲求なのか。
4. どの証拠からそう判断したか。
5. 自分たちが使うなら、何を残して何を変えるか。

## 4. 情報設計

### 4-1. Radar — 初期画面

主役は「上昇中クラスタ」。各行に以下を表示する。

- ランクとライフサイクル: emerging / accelerating / mainstream / cooling
- クラスタ名: 例「失敗を先に見せるHow-to」
- 速度、投稿者への伝播、複数レーン一致、複数媒体一致
- 24時間sparkline
- 3層要約: 表層 / 構造 / 欲求
- 代表投稿3件
- Bias Auditラベルと「市場トレンド / チーム内注目」の区別
- 確信度と反証
- 保存件数ではなく、独立投稿者数を強調

上部には`Mac online`、最終同期、待機ジョブ、無料枠使用率を常時表示する。

### 4-2. Trend Detail — 証拠画面

```text
トレンド名 / 状態 / confidence
├─ なぜ今トレンドと判断したか
├─ 伝播タイムライン
├─ Platform × Lane マトリクス
├─ 表層記号
├─ 表現構造
├─ 根底欲求
├─ Bias Audit（人手選択の偏りと独立確認）
├─ 証拠動画（最初期・最速上昇・媒体横断・反例）
├─ ライフサイクル予測
└─ 活用案 / 適合スコア / 採用後の実績
```

AI要約だけを見せず、すべての結論から元投稿・観測値へ辿れるようにする。

#### Bias Audit表示

- 人手送信比率、送信者集中度、人手以外の観測レーン数、独立確認率を表示する。
- 同じ動画を複数メンバーが送った件数は「チーム内注目」として表示し、市場の伝播件数とは分ける。
- `低 / 中 / 高`だけでなく「何がスコアから除外されたか」を文章で示す。
- 高リスク時は緑のトレンド表示を使わず、「チーム内注目・独立確認待ち」とする。

#### 証拠動画カード

各トレンドに標準で最大6件を表示し、以下の役割を最低1件ずつ選ぶ。存在しない役割は無理に埋めない。

1. 最初期に確認した投稿
2. 最速で伸びた投稿
3. 別媒体へ伝播した投稿
4. 仮説に合わない反例

カードにはサムネイル、媒体、投稿者、公開日時、証拠役割、観測時の数値、通常値比、発見レーン、最終リンク確認日時、「なぜ根拠に含めたか」を表示する。`Instagramで開く`等のボタンは`posts.canonical_url`を新しいタブで開く。ログインが必要な場合はその旨を表示し、削除済み・閲覧不可はリンク状態を残して代替証拠へ誘導する。動画本体は保存しない。

### 4-3. Inbox — 収集処理

- Bot / 拡張 / 自動巡回から届いたリンク
- 候補保存、Bias Audit待ち、独立確認済み、トレンド認定、チーム内注目、失敗
- 重複時は「既存投稿 + 新しい発見経路」と表示
- メンバーのメモと1タップタグ
- 失敗してもURLは残す

### 4-4. Coverage — フィルターバブル監査

- 4観測レーンの構成比
- プラットフォーム比
- ジャンル、言語、地域、投稿者規模の分布
- 上位投稿者への集中度
- 調査アカウント同士の重複率
- 過去7日で欠けたレーンの警告

### 4-5. Compare — 比較

2〜4トレンドを横並びにし、速度、広がり、寿命、制作難易度、ブランド適合、証拠量を比較する。会議で採用候補を決める画面。

### 4-6. Automation — 稼働状態

- Mac online / offline
- Instagram / TikTok / YouTubeコネクタ状態
- 最終巡回、次回巡回、現在の画面、直近エラー
- 取得数、重複数、分析待ち
- Jev token、Cloudflare request、YouTube quota
- 緊急停止ボタン
- 書き込み操作が0件であることを監査ログで表示

## 5. 権限

| Role | 操作 |
|---|---|
| Viewer | Radar、Trend Detail、Compare、Coverageの閲覧 |
| Collector | リンク保存、メモ、タグ付け |
| Analyst | クラスタ統合・分割、ラベル修正、トレンド認定 |
| Admin | メンバー、Bot、巡回、無料枠、緊急停止 |

初期は招待コードで登録し、ユーザーごとにsessionを発行する。メール・SMS認証は使わない。

## 6. モバイル

- Botが主な保存入口なので、モバイルWebは閲覧・確認に絞る。
- Radarは1列、Trend Detailはセクション折りたたみ。
- 代表投稿を外部SNSアプリで開ける。
- 具体動画リンクは正規URLだけを使用し、プロトタイプの架空URLを本番データへ混ぜない。
- Botへ戻る「リンクを保存」導線を固定する。

## 7. 初期実装する4画面

1. Radar
2. Trend Detail
3. Coverage
4. Automation

InboxはRadar右側のドロワーから開始し、CompareはTrend Detailが2件以上揃ってから追加する。

## 8. 完了条件

- Macの分析完了から15秒以内に別端末のRadarへ反映される。
- 各トレンドから根拠投稿まで2クリック以内で辿れる。
- 各根拠動画に証拠役割と採用理由があり、正規URLを直接開ける。
- Bot投稿だけで広域トレンドに昇格せず、Bias Auditの内訳と除外件数を確認できる。
- 4レーンの偏りが常時見える。
- Mac offline、同期遅延、無料枠80%超過を画面上で判別できる。
- Instagram / TikTokの書き込み操作件数が常に0と確認できる。
