**対象読者**: 次の開発担当エージェント

## 1. 開発目的

YouTube Shorts、Instagram Reels、TikTokの短尺動画を広く観測し、単なる再生数ランキングではなく、複数クリエイター・複数観測経路への伝播からトレンドを検出する。分析結果をSNS運用とマーケティング企画へ転用できる独立ツールとして提供する。

## 2. 絶対要件

| 項目 | 開発要件 |
|---|---|
| 製品境界 | 既存アプリへ統合せず、独立したWeb・Bot・収集・分析システムにする |
| 費用 | 外部サービス請求0円。無料枠80%で警告し、上限時は課金せず停止またはローカルへ退避 |
| データ正本 | 自宅MacのSQLite。DuckDBは再生成可能な分析層、D1は閲覧用read model |
| Git | コード、schema、migration、匿名seedのみ。DB、Cookie、token、観測データは入れない |
| 収集入口 | Discord Botを主入口、Slackを社内第2入口、PCはChrome拡張 |
| 自動巡回 | Instagram / TikTokを専用調査アカウントで閲覧・スクロール・公開表示情報記録まで自動化 |
| 禁止操作 | like、follow、comment、投稿、repost、DM、購入、設定変更を実行しない |
| 動画 | 動画ファイルを保存しない。正規URL、許可されたメタデータ、観測値だけを保存 |
| 分析 | 表層記号・表現構造・根底欲求の3層クラスタを持つ |
| スコア | 広域トレンド、チーム内注目、活用適合を別スコアにする |
| バイアス | 人が送った投稿は候補扱い。独立確認まで広域伝播数に加算しない |
| 証拠 | 各トレンドから最初期・最速上昇・媒体横断・反例の具体投稿を開ける |
| 公開 | 非商用期間はGitHub→Vercel Hobby。APIはCloudflare Worker、共有閲覧DBはD1 |
| シート | 既存Googleスプレッドシートを編集しない。事務担当の変更後にGAS連携する |

## 3. 観測とトレンド判定

### 3-1. 4観測レーン

1. Personalized: メンバーが日常利用中に発見
2. Fixed Panel: 固定クリエイター・固定テーマの継続観測
3. Broad Discovery: 毎週入れ替える検索語・隣接ジャンル
4. External Baseline: 公式API、ランキング、外部基準

`auto_observed`は第5レーンではなく取得方法。Fixed Panel / Broad Discovery / External Baselineのいずれかへ所属させる。

### 3-2. 初期トレンドゲート

- 独立クリエイター3人以上
- 人手送信以外の観測レーン2つ以上
- 自動巡回または公式ソースによる独立確認1件以上
- 時系列snapshot 2点以上で増加を確認
- 転載集中率が上限未満
- 共通する表層記号または表現構造が存在

絶対再生数は条件にしない。閾値と重みは300〜500件の正解ラベル後に校正する。

### 3-3. Bot投稿のBias Audit

- 同一URLを複数人が送っても、`capture_events`は複数、投稿証拠は1件。
- 共有数は`team_interest_score`へ入れ、`diffusion_score`へ入れない。
- 人手送信比率、送信者HHI、独立確認率、非人手レーン網羅から0〜100のriskを算出。
- 0〜39は独立確認後に通常反映、40〜69は暫定、70以上は広域ランキングから外す。
- ユーザー入力の再生数はスコアに使わず、媒体表示値または公式APIからsnapshotを作る。

## 4. システム構成

```text
Discord / Slack / Chrome拡張 / 自動巡回 / YouTube API
                         ↓
                Capture API / D1受信キュー
                         ↓ Macが外向き取得
        SQLite正本 → DuckDB分析 → sync_outbox
                         ↓
               Cloudflare Worker + D1
                         ↓
          GitHub → Vercelの独立Web管理画面
                         ↓
       GAS → 既存スプレッドシートのRadar取込
```

Macへ外部から直接接続させない。Mac停止中の入力はD1受信キューへ保持し、復帰後に回収する。

## 5. 初期リリースの画面

1. Radar: 上昇中クラスタ、市場/チーム内注目の区別、証拠数、独立投稿者数
2. Trend Detail: 3層分析、伝播、Bias Audit、具体動画カード、反証
3. Coverage: 4レーン、媒体、言語、地域、投稿者規模、集中度の偏り
4. Automation: Mac・各コネクタ・無料枠・書き込み操作0件の監査
5. Inbox: 初期はRadarのドロワー。候補→監査待ち→独立確認→認定/チーム内注目を表示

各証拠カードは`posts.canonical_url`を新しいタブで開く。`active / login_required / deleted / unavailable`と最終確認日時を保持する。架空URLを本番へ入れない。

## 6. 実装順

### Phase 0 — リポジトリ初期化

- TypeScript + pnpmで独立リポジトリを作る
- lint、test、migration、`.env.example`、秘密情報除外を設定
- Mac worker / Worker API / Web / Bot / extensionの境界を固定

### Phase 1 — Capture Backbone

- SQLite schemaとmigration
- URL媒体判定、canonicalize、重複排除
- `POST /api/captures`、`GET /api/posts/:id`
- `capture_events`とD1受信キュー
- unit test

### Phase 2 — BotとYouTube

- Discord Bot、Slack Socket Mode
- リンクのみで保存完了、タグ・メモは任意
- YouTube Data API adapterとquota guard
- ユーザーIDの匿名化

### Phase 3 — Webと同期

- sync_outbox、Worker API、D1 read model
- 招待コードとrole
- Radar / Trend Detail / Coverage / Automation
- 15秒polling、Mac offline表示

### Phase 4 — Chrome拡張と自動巡回

- Manifest V3、activeTab、offline queue
- Instagram / TikTokの閲覧専用Playwright worker
- 許可操作allowlist、書き込み操作0件監査、緊急停止
- CAPTCHAやUI変更時は停止して要確認にする

### Phase 5 — Analysis

- metric snapshot、通常値比、ロバスト上振れ
- 3層feature、ローカルembedding、階層cluster
- Bias Audit、広域スコア、team interest、fit score
- Jevは曖昧分類と画面判断だけに限定し、上限時はruleへfallback

### Phase 6 — GAS連携と仕上げ

- 事務担当によるシート変更完了後にGASを実装
- `trend_id` upsert、HMAC、成果逆連携、CSV fallback
- end-to-end test、バックアップ・復旧手順、運用監視

## 7. Definition of Done

- Discord / Slack / Chrome拡張のリンクが同じCapture APIへ入り、同一投稿を重複生成しない。
- Bot投稿だけでは市場トレンドへ昇格しない。
- Bias Auditの内訳、除外件数、独立確認状況を画面で説明できる。
- 各トレンドから役割付きの実投稿URLへ2クリック以内で移動できる。
- 分析完了から15秒以内に別端末へ反映される。
- Mac停止中の入力を失わず、復帰後に処理できる。
- Instagram / TikTokへの書き込み操作がテスト・監査ログとも0件。
- 外部サービス請求0円で、無料枠超過時に課金されない。
- DB、token、Cookie、動画本体がGitやD1へ混入しない。
- 既存スプレッドシートの数式・入力規則・人入力列を壊さない。
- mobile / desktopで主要導線が使え、主要操作に自動テストがある。

## 8. 未決事項と実装時の扱い

| 未決 | 実装を止めない暫定値 |
|---|---|
| 最初の対象地域・言語 | `ja-JP`をseedにし、設定変更可能にする |
| 固定クリエイターパネル | 空の管理画面とimport機能を先に作り、リストをhardcodeしない |
| Bias Auditの重み | 仕様v1の仮値。設定テーブル化する |
| Jevの実利用量 | 月次上限とkill switchを先に作り、1週間の実測後に調整 |
| チュートリアル導入 | 開発完了後に本人が必要性を判断する |

## 9. 開発時の禁止事項

- Instagram / TikTokの反応・投稿操作を実装しない。
- CAPTCHA回避、アクセス制限回避、アカウント停止回避を実装しない。
- 実在しない投稿URLや観測値を本番データへ入れない。
- 本人承認前にAPI登録、課金、外部デプロイ、シート編集をしない。
- SQLite / DuckDB、秘密情報、ブラウザprofileをGitへ追加しない。
- AI要約だけで判定を完結させず、元投稿と計算内訳を残す。
