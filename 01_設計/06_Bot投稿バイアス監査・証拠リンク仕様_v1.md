# Bot投稿バイアス監査・証拠リンク仕様 v1

**状態**: レビュー待ち  
**作成日**: 2026-10-09

## 1. 結論

ユーザーがBotへ送った動画は、最初から「市場トレンドの証拠」にはしない。まず「チームが気になった候補」として保存し、自動巡回・公式ソース・別観測レーンで独立確認できた分だけ広域トレンドへ反映する。

画面では市場の広がりとチーム内の関心を並べて見せる。各トレンド群には実際の投稿URLを役割付きで置き、要約から元動画まで2クリック以内で辿れるようにする。

## 2. なぜ必要か

Bot投稿には次の選択バイアスがある。

- 送信者の担当領域、年齢、趣味、フォロー関係に偏る
- すでに伸びた目立つ動画だけを選びやすい
- チーム内で共有された同じ動画が重複して送られる
- 特定の熱心な1人が投稿件数の大半を占める
- 表示再生数の大きさを「広く伝播したこと」と誤認しやすい

したがって「何人が送ったか」と「市場で何人の独立クリエイターが同じ構造を使ったか」を別の指標にする。

## 3. 判定パイプライン

```text
Bot / 拡張からリンク受信
        ↓
チーム内候補として保存 ──→ team_interest_score
        ↓
URL重複・送信者集中・数値出典を監査
        ↓
自動巡回 / 公式API / 固定パネル / 外部基準で独立確認
        ↓
┌──────────────────────┬──────────────────────┐
│ 独立確認できた         │ 確認できない・偏り大   │
│ 市場トレンド候補へ反映 │ チーム内注目に隔離     │
└──────────────────────┴──────────────────────┘
        ↓
独立投稿者3人以上 + 人手以外2レーン以上で認定判定
```

## 4. Bias Audit

### 4-1. 表示する4指標

| 指標 | 意味 | 危険な状態 |
|---|---|---|
| 人手送信比率 | 根拠候補に占めるBot・拡張送信 | 高い |
| 送信者集中度 | 特定メンバーへの偏り。匿名IDのHHI | 高い |
| 独立確認率 | 人手以外で再発見できた投稿・類似構造 | 低い |
| 非人手レーン網羅 | 自動・公式経由で確認した観測レーン | 少ない |

初期のバイアスリスクは加重平均で0〜100にする。重みは人手送信比率35%、送信者集中度25%、独立確認不足25%、レーン不足15%。これは正解ラベル300〜500件が集まるまでの仮値で、固定仕様ではない。

### 4-2. ゲート

| Bias risk | 扱い |
|---|---|
| 0〜39 | 独立確認済みなら市場スコアへ通常反映 |
| 40〜69 | 暫定表示。確信度を下げ、警告を付ける |
| 70〜100 | 広域ランキングから外し「チーム内注目」に置く |

広域トレンドの最低条件は、独立クリエイター3人、人手送信以外の観測レーン2つ、自動巡回または公式ソースの確認1件とする。

### 4-3. 重複の扱い

- 同じURLを5人が送信: `capture_events`は5件、投稿証拠は1件、チーム関心は5件。
- 同じ投稿の転載URL: 同一性が確実なら1つのoriginへ束ね、転載集中率を別表示。
- 別クリエイターが同じ型を制作: 独立投稿者として数える。
- ユーザー入力の再生数: メモには残せるが、数値スコアには使わない。

## 5. 画面仕様

### 5-1. Radar行

```text
失敗を先に見せる How-to     市場トレンド  34 creators
Bias 28 / LOW               人手投稿14件は伝播数から除外
```

偏りが高い候補は次のように表示する。

```text
社内で話題の無音Vlog          チーム内注目  11 shares
Bias 82 / HIGH               独立確認 0件・上位1名が73%
```

### 5-2. Trend DetailのBias Audit

- バイアスリスクと判定ラベル
- 人手送信比率
- 上位送信者の寄与またはHHI
- 人手以外の観測レーン `3 / 4`
- 独立確認率
- 除外したチーム共有数
- 現在の判定理由を1文で表示

### 5-3. 証拠動画カード

各トレンドは標準で最大6件。以下の証拠役割を優先する。

| 役割 | 選定規則 |
|---|---|
| 最初期 | クラスタ内で`published_at`が最も早く、リンク確認済み |
| 最速上昇 | 同条件内の速度順位が最上位 |
| 媒体横断 | 発生元とは別媒体で最初に確認 |
| 反例 | 構造は近いが伸びなかった、または仮説に反する |

カード項目:

- サムネイルまたは媒体別プレースホルダー
- 媒体、投稿者、公開日時
- `最初期`等の証拠役割
- 観測時の再生・いいね等と通常値比
- 発見レーンとデータ出典
- 「この動画を含めた理由」
- 正規URLを開くボタン
- 最終リンク確認日時と状態

リンク状態は`active / login_required / deleted / unavailable`。外部リンクは新しいタブで開き、`noopener noreferrer`を付ける。ログインが必要でも正規URLを保持し、削除済みでも観測値と削除日時は証跡として残す。動画ファイルは保存しない。

## 6. API read model

`GET /api/trends/:id`は次を分離して返す。

```json
{
  "universalScore": 81,
  "teamInterestScore": 67,
  "biasAudit": {
    "riskScore": 28,
    "label": "low",
    "userSubmittedShare": 0.31,
    "submitterHhi": 0.14,
    "independentConfirmationRatio": 0.78,
    "nonUserLaneCount": 3,
    "excludedTeamShares": 14
  },
  "evidencePosts": [
    {
      "role": "earliest",
      "canonicalUrl": "<stored canonical URL>",
      "linkStatus": "active",
      "whyIncluded": "最初期に確認できた独立投稿",
      "lastVerifiedAt": "<timestamp>"
    }
  ]
}
```

D1へは表示に必要な証拠URLと集計値だけを同期する。BotのユーザーIDは同期せず、匿名化済み集計だけを送る。

## 7. 完了条件

- Bot投稿だけでは広域トレンドへ昇格しない。
- 同じ動画の複数共有が独立伝播として数えられない。
- 市場スコアとチーム内注目度を別々に確認できる。
- 全トレンドから役割付きの具体動画へ2クリック以内で移動できる。
- 架空URLを本番データへ入れず、収集した正規URLだけを表示する。
- リンク切れやログイン必須を画面で判別できる。
